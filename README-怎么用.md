# 自驾路书制作 Skill · 使用说明

一个把「目的地」变成「一本能发出去的路书」的工具包。
产物是单文件 HTML（可打印 A4）+ 飞书云文档，地图全部自制 SVG。

---

## 一、它到底怎么启动

**不用记命令。** 装好之后，你跟 AI 说一句话就行：

> 「帮我做一本川西小环线 5 天的自驾路书」

AI 会自动认领这个 Skill，然后按 S1 到 S6 六个阶段往下走。

命令行的部分是我（AI）去跑的，你只需要在三件事上做决定：

1. 去哪儿、几天、落地租车还是自己开车
2. 给谁看（情侣 / 一家三口 / 带老人）
3. 每章的初稿要不要改

---

## 二、给自己装（本机已装好，跳过这节）

位置：`~/.workbuddy/skills/roadbook-maker/`

如果哪天换电脑，把这个文件夹整个拷到新机器的同一位置即可。
**装完必须新开一个对话窗口**，Skill 只在会话开始时加载。

---

## 三、给别人装（三步）

### 第 1 步：打包

把 `roadbook-maker` 整个文件夹压缩成 zip 发给对方。

### 第 2 步：放到指定位置

对方解压后，把文件夹放到：

```
Windows:  C:\Users\<用户名>\.workbuddy\skills\roadbook-maker\
Mac/Linux: ~/.workbuddy/skills/roadbook-maker/
```

注意：`.workbuddy` 是隐藏文件夹，Windows 上要在地址栏直接输入路径才能进去。

### 第 3 步：检查依赖

让对方新开一个对话，说：

> 「帮我检查一下 roadbook-maker 这个 skill 能不能跑」

AI 会跑一遍体检，缺什么会直接说。三个可选依赖：

| 依赖 | 缺了会怎样 | 怎么补 |
|---|---|---|
| Python 3.11+ | 完全跑不了 | WorkBuddy 自带，一般不用管 |
| playwright + 浏览器 | 出不了 PNG，飞书文档里没图 | 只影响交付形态，HTML 照样能出 |
| lark-cli 已登录 | 传不了飞书 | 只交本地 HTML，自己打印成 PDF |

## 四、五个命令（想手动跑的时候用）

在书稿目录下执行（就是 `book.toml` 所在的那个文件夹）：

```bash
python roadbook.py init ./我的路书 --title "书名" --author "署名"   # 新建
python roadbook.py doctor .        # 体检：缺章、缺图、占位框对不上
python roadbook.py build .         # 合并成单文件 HTML
python roadbook.py png .           # SVG 转 PNG（飞书要用）
python roadbook.py feishu .        # 转飞书格式并上传，返回文档链接
```

`doctor` 永远第一个跑，它会把「哪一章少了一张图」「哪个占位框没有配图」直接点名。

---

## 五、一本书的目录长什么样

`init` 之后是这样：

```
我的路书/
  book.toml            ← 唯一配置文件：章节顺序、图号、图注、宽度
  01-封面与目录.html   ← 各章正文，一章一个文件
  figs/                ← 出图脚本产出的 SVG
  figs-png/            ← 渲染出的 PNG（自动生成，不用手管）
```

**只改 `book.toml`，不要改脚本。** 加一章就加一段 `[[chapter]]`，加一张图就加一段 `[[figure]]`。

---

## 六、写一章的最小模板

复制 `assets/章节-模板.html`，改内容就行。结构固定成这几块：

1. `h1` 章标题 + `p.sub` 副标题
2. 行程总览表（几点、去哪、多少公里、门票多少）
3. 上午 / 下午分段写
4. `div.advice` 我的建议
5. `div.warn` 注意事项
6. `div.meta` 数据来源与核验日期

插图位置放这一行，`data-fig` 写图的 id：

```html
<div class="imgph" data-fig="fig-03-day2-route">地图位置：第二天路线</div>
```

## 七、三个最容易翻车的地方

1. **地图上的字挤在一起。** 点位密集时必须用「编号框 + 右侧清单」，不要硬塞文字。生成后一定要亲眼看一遍 PNG。
2. **同一景点两处写不一样。** 比如 Day2 写「3.5 小时」，附件写「2.5 小时」。所有数字只在一处维护，其他章节引用。
3. **飞书高亮块里放表格会失败。** 表格要拆到 callout 外面。

完整的 21 条陷阱在 `references/pitfalls.md`，写书前花三分钟读一遍能省三小时。

---

## 八、它不适合干什么

- 只要一份景点清单或「哪里好玩」的推荐（直接问，不用建书）
- 单篇游记、种草文案
- 没有行程结构的旅行问答

这些场景做出来会「规格过大」，一本书的排版成本远高于回报。
